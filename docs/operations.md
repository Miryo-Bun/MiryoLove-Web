## Пользователь службы и доступ

Caddy запускается от `caddy:caddy`. В предыдущей проверке родительские каталоги deployment имели mode `755`, а файлы — `644`; в этой проверке права не менялись. Caddy под пользователем `caddy:caddy` обслуживает страницы из этого root, но отдельное read-test от effective UID не выполнялся. `/var/log/caddy` имеет mode `750`, владелец `caddy:caddy`; текущему пользователю каталог недоступен для списка, поэтому наличие/содержимое файла access log не проверено. Точного production log path кандидат от `caddy` не валидировался.

## Production-применение

Никакие production-команды не выполнялись. **Текущий полный Caddy-кандидат не применять**: он содержит site blocks, отсутствующие в active config. Перед любым изменением администратору следует:

1. Получить отдельное разрешение и выяснить историю изменения файла/runtime.
2. Подготовить минимальный кандидат, соответствующий актуальной конфигурации; не использовать `deploy/Caddyfile.candidate` без независимого пересмотра.
3. Создать уникальную административную резервную копию и проверить staged-файл.
4. Проверить право `caddy` на log path только если новый файл действительно согласован; команда validation может создать файл.
5. Получить отдельное разрешение на применение/reload.
6. После разрешённого переключения проверить HTTPS, все routes, redirects, query strings и 404 по процедуре в `deployment.md`.
7. При ошибке откатывать только по отдельно согласованной проверенной резервной копии.

Не менять DNS, права, владельцев, журналы, базы данных, snapshots и другие сервисы в рамках этого runbook.

## Логи и приватность

В активном основном site block отдельный access log не включён, однако Caddy пишет системные диагностические, TLS- и ACME-сообщения в systemd journal. В подготовленном, пока не применённом кандидате добавлен `/var/log/caddy/miryolove-access.json`: UTC timestamp и сырой User-Agent как единственное поле из запроса; статические поля JSON Caddy сохраняются. IP, request object, URL/path/query, Referer, cookies, прочие headers, status и timing-поля удаляются. Настроены rotation 10 MiB, семь файлов и удаление старше 14 дней. Валидация с фактическим `/var/log/caddy` должна быть выполнена от имени `caddy`, чтобы не создать файл с неверным владельцем; она может создать новый журнал и требует предварительного разрешения. Raw User-Agent всё ещё может быть уникальным. Systemd journal retention не установлена; ошибки Caddy могут включать IP или детали запросов. Старые журналы не удалялись.

Не считать фильтрацию access log фильтрацией всех журналов. Не публиковать реальные IP, User-Agent, заголовки, query strings или значения запросов.
