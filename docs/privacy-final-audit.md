# Итоговый технический аудит приватности MiryoLove

**Дата проверки:** 7 ноября 2026 года  
**Статус:** технический отчёт для последующей проверки владельцем и юристом. Это не заключение о соответствии 152-ФЗ.

## Краткий вывод

В проверенных исходниках и публичной копии сайт является статическим. Формы отправки данных, аналитика, рекламные пиксели, встроенные внешние страницы, внешние шрифты и клиентские API-запросы не обнаружены. Код сохраняет выбор языка в `localStorage` и закрытие уведомления в `sessionStorage`; эти значения не отправляются сайтом. В проверенных production GET-ответах `Set-Cookie` не обнаружен.

Отсутствие формы, cookie и access log не означает отсутствия обработки технических данных при установлении сетевого соединения или в нижележащих слоях инфраструктуры. Доступные сведения не устанавливают всех получателей, целей, правовых оснований и сроков хранения. Юридическое соответствие не оценивалось и не подтверждается этим документом.

## Установленные факты

### Сайт и browser storage

- Проверены исходный сайт и `MiryoLove Web-deploy`; публичная копия содержит статические HTML/CSS/JavaScript и ресурсы сайта.
- В просмотренном коде нет форм, прикладных API-запросов, аналитики, рекламных пикселей, iframe, автоматически загружаемых сторонних скриптов или внешних веб-шрифтов.
- `localStorage` хранит выбранный язык (`ru`/`en`); `sessionStorage` — состояние закрытия информационного уведомления в текущей вкладочной сессии. Код сайта эти значения не отправляет.
- В проверенном коде не найден `document.cookie`, IndexedDB, Service Worker или Cache Storage.
- Read-only HTTPS GET-проверки 7 ноября 2026 года для главной страницы, canonical pages, JS/CSS/sitemap/robots и неизвестного пути не выявили `Set-Cookie`. Страницы и ресурсы ответили 200, неизвестный путь — 404; TLS verification прошла. Проверка не эквивалентна исчерпывающему анализу всех HTTP-методов, клиентов и сетевых посредников.

### Caddy и серверные журналы

- Служба Caddy работает как `caddy:caddy`, загружая `/etc/caddy/Caddyfile`.
- Текущий доступный disk Caddyfile и read-only runtime admin API указывают на root `/mnt/Manchild/Project/MiryoLove/MiryoLove Web-deploy`; активны только `miryolove.org` и `www.miryolove.org`. Reverse proxy, imports и access logging для текущего сайта не обнаружены.
- Ранее зафиксированное наблюдение root `/mnt/Manchild/Project/MiryoLove/Web/1` устарело. Нынешний Caddyfile имеет mtime позже старта процесса; точные время, причина и инициатор изменения/reload не установлены.
- Стандартный вывод Caddy направлен в systemd journal. За последние семь дней обнаружено 4 323 Caddy events; 110 структурированных request objects отнесены к другим hosts. В записях присутствовали поля IP, URI и headers; Referer был в 85, Cookie — в 34 объектах. Значения не копировались в отчёт. Эти исторические записи не подтверждают аналогичное журналирование запросов главного сайта.
- Общий journald занимает около 1.2 GB. Явные настройки срока хранения/лимита не обнаружены; срок фактического хранения и доступ к ранее накопленным записям остаются неустановленными.
- `/var/log/caddy` имеет mode `750`, владелец `caddy:caddy`; текущему пользователю отказано в чтении списка каталога. Наличие файлов и их содержимое не установлены. Отдельное правило logrotate для Caddy не обнаружено в доступной проверке.
- Snapper timeline/cleanup timers активны, но конфигурация хранения и список snapshot недоступны без повышенных прав. В `/var/log` также обнаружены файлы Cloudflare WARP и Snapper; их содержимое и связь с трафиком сайта не проверялись.

### Тест кандидата access log и ограничения

- Изолированный Caddy-тест искусственного запроса подтвердил, что запись тестового кандидата содержит `ts`, `level`, `logger`, `msg` и искусственный `visitor_user_agent`. Timestamp — Unix epoch, соответствующий UTC.
- Тестовые IP, URL/query, Referer, Cookie, Authorization, другие headers, body и response metrics в запись не попали. Это результат только изолированной тестовой копии, а не работающего production-журнала.
- Локальный `deploy/Caddyfile.candidate` устарел относительно текущей active config: в нём сохранены дополнительные AI/press site blocks и access-log настройки с output `/var/log/caddy/miryolove-access.json`, ротацией 10 MiB/до 7 файлов и сроком до 14 дней. Не применять этот кандидат без новой сверки и отдельного согласования.
- Validation точного старого кандидата с production log path для текущего пользователя завершился `permission denied`; копия с временным writable output path прошла validation. Это не подтверждает права службы `caddy` на production path и не является проверкой доступа к реальным логам.

## Не установлено

1. Юридическое и фактическое лицо оператора, официальный контакт и полномочия принимать решения.
2. Утверждённые цели и правовые основания каждой операции обработки.
3. Провайдеры хостинга, DNS, CDN/proxy, сетевые посредники, поддержка и их субподрядчики; местоположение систем и возможные трансграничные передачи.
4. Журналирование вне доступного Caddy/systemd слоя, роли доступа, резервное копирование логов и документированные сроки удаления.
5. Snapper/backup retention, шифрование, регионы и фактические группы доступа.
6. Полный состав данных, получателей и сроков обработки на инфраструктурных уровнях.
7. Юридическая достаточность опубликованных privacy/cookie документов и применимость конкретных требований закона.

## Границы выполненных действий

Проверка была read-only для production. Активный `/etc/caddy/Caddyfile` не изменялся, Caddy не перезапускался, DNS и firewall не менялись, журналы, базы данных и snapshots не удалялись, права и владельцы не изменялись. Никаких уведомлений в Роскомнадзор не направлялось. Значения запросов, IP посетителей и содержимое потенциально идентифицирующих полей в отчёт не включались.
