# Заметки по безопасности и ограничения проверки

**Дата:** 7 ноября 2026 года
**Область:** локальные source/deploy файлы и конфигурация Caddy, доступная чтению. Это не penetration test, не аудит всей инфраструктуры и не юридическое заключение.

## Проверено

- Deployment содержит только статические HTML/CSS/JS, три локальных изображения, sitemap и robots. В нём нет `.git`, `docs/`, скрытых файлов, симлинков, внутренних отчётов и конфигураций разработки.
- Проверка распространённых шаблонов приватных ключей и известных форм токенов по deployment совпадений не выявила. Это ограниченный поиск шаблонов; он не доказывает отсутствие всех секретов или уязвимостей.
- В просмотренном клиентском сайте нет форм отправки, авторизации, API-клиентов, WebSocket, аналитических пикселей, встроенных сторонних страниц или автоматически загружаемых внешних шрифтов. Язык сохраняется в `localStorage`, закрытие информационного уведомления — в `sessionStorage`; код сайта не отправляет эти значения.
- Доступный Caddy admin API подтвердил runtime root `/mnt/Manchild/Project/MiryoLove/MiryoLove Web-deploy`, hosts apex и `www`, отсутствие reverse proxy и access logging. Текущий `/etc/caddy/Caddyfile` имеет тот же root; Caddy работает от `caddy:caddy`.
- В текущем полном кандидате остаются site blocks AI/press, отсутствующие в active config. **Не применять этот кандидат** без подготовки нового минимального согласованного файла.
- Изолированный тест будущего access log оставил `ts`, статические `level/logger/msg` и только тестовый `visitor_user_agent`; IP, URL/query, Referer, Cookie, Authorization, другие headers, body и response metrics отсутствовали. UNIX timestamp соответствует UTC. Этот результат относится только к временной тестовой копии; active site logging не включён, `/var/log/caddy` недоступен для проверки текущим пользователем.
- В journald за последние семь дней обнаружено 110 структурированных Caddy error/reverse-proxy records с request headers; все отнесены к host, отличным от главного домена. В объектах присутствовали IP-поля, URI и заголовки; в 85 записях был Referer, в 34 — Cookie. Значения не выводились. Эти записи показывают, что systemd journal способен сохранять запросные данные; это не access log основного сайта.
- Read-only HTTPS-проверки 7 ноября 2026 года прошли: canonical pages/ресурсы — 200, неизвестный путь — 404, TLS verification — 0, проверенные GET не содержали `Set-Cookie`. Текущие HTTP→HTTPS и `www`→apex redirect сохраняют query; redirects с clean path без `/`, legacy `.html` и снятой roadmap теряют query.

## Нерешённые вопросы и пределы проверки

- Предыдущая проверка сообщала root `/mnt/Manchild/Project/MiryoLove/Web/1`; текущие file config и runtime API указывают на deployment-каталог. Историю изменения/reload нельзя вывести из времени запуска процесса.
- Журналы Caddy направляются в journald (`StandardOutput=journal`). Общий journal занимает 1.2 GB; явные `SystemMaxUse`/`MaxRetentionSec` значения не заданы, retention неизвестен. `/var/log/caddy` mode `750`, владелец `caddy:caddy`; его содержимое недоступно текущему пользователю. Для Caddy отдельного logrotate правила не обнаружено.
- В `/var/log` есть файлы Cloudflare WARP, Snapper и системных компонентов; их содержимое и связь с обработкой запросов сайта не изучались. Snapper timeline/cleanup timers активны, но конфигурация хранения недоступна без прав.
- Deployment пути имеет mode `755`, файлы `644`; это допускает доступ пользователя `caddy` по разрешениям `other`. Команда фактического чтения от effective UID Caddy не выполнялась.
- Создан локальный снимок содержимого активного Caddyfile в session storage; SHA-256 совпал с активным файлом при создании. Это не административная резервная копия с системными атрибутами. В `/etc/caddy` ничего не записывалось; существовавшие backup-файлы не менялись.
- Не выполнялись поиск уязвимостей, тестирование проникновения, проверка сервера/ОС, DNS-панелей, приватных резервных копий, firewall или других услуг.
- Отдельная директива `Content-Security-Policy` не добавлялась; её внедрение требует отдельной проверки inline-ресурсов и тестирования.
- Caddy access log с лимитом ротации/хранения 14 дней только подготовлен и не включён. Журналы вне текущего access path, получатели данных, сроки хранения, доступ и инфраструктурные меры требуют отдельной проверки администратора и юридического специалиста. User-Agent может относиться к персональным данным в зависимости от контекста обработки.

## Вывод

По имеющимся данным сайт статический, в нём не обнаружены формы, аналитика или автоматическая загрузка сторонних скриптов. Это не доказывает отсутствие обработки данных другими слоями инфраструктуры и не является юридическим выводом. В ходе этой задачи Caddy, DNS, службы, журналы и права не менялись. Перед любым изменением конфигурации требуется отдельное решение владельца; текущий кандидат не применять.
