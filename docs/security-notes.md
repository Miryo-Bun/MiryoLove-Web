# Инженерные заметки по безопасности хоста MiryoLove Web

**Дата фиксации параметров:** 7 ноября 2026 года  

## 1. Аппаратная изоляция и среда выполнения
* **Платформа:** Физический сервер Bare Metal (MSI), операционная система Arch Linux.
* **Преимущество схемы:** Исключены риски несанкционированного доступа к накопителям или копирования дампов памяти на уровне облачного гипервизора сторонних хостинг-провайдеров. Вся физическая безопасность оборудования контролируется владельцем хоста.

## 2. Безопасность логирования и минимизация рисков
* **Caddy Access Log:** Файл логов доступа расположен по пути `/var/log/caddy/miryolove-access.json` и защищен правами доступа (`mode 0600`, владелец `caddy:caddy`). Выборочная проверка подтвердила, что фильтрация полностью исключает накопление IP-адресов и заголовков (User-Agent, Cookies) в JSON-строках.
* **Systemd Изоляция:** Параметр `LogNamespace=caddy` успешно разделяет диагностику веб-сервера и системные логи ОС. Журналы Caddy хранятся обособленно в `/var/log/journal/...caddy`.

## 3. Контролируемые эксплуатационные риски
1. **Текстовое поле MESSAGE:** При критических сбоях runtime-компонентов или падении reverse-proxy (если он будет внедрен) существует потенциальный риск сброса отладочной информации (включая фрагменты заголовков) в текстовое поле `MESSAGE` системного журнала. Требуется периодический контроль структуры диагностических записей.
2. **Исторический след логов:** Сообщения, сгенерированные до миграции службы Caddy в изолированный namespace, физически остаются в общих архивных файлах `journald` хоста до момента их планового вытеснения по объему.
3. **Общесистемные бэкапы:** При использовании инструментов автоматических снимков файловой системы (например, Snapper) архивы логов могут дублироваться в снимках дисков. Сроки их хранения определяются общесистемной политикой ротации хоста.

## 4. Рекомендации по дальнейшей эксплуатации
* При развертывании тестовых конфигураций валидацию файлов (`caddy validate`) проводить строго с указанием временных writable путей, чтобы не нарушать права доступа на рабочие каталоги логов.
* Не отключать встроенные заголовки безопасности веб-сервера (Helmet-эквиваленты, CORS-ограничения), обеспечивающие базовую защиту статического фронтенда от XSS и Clickjacking.
