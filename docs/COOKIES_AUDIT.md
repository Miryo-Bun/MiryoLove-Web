# MiryoLove Web — cookies and browser-storage audit

**Review date:** 4 November 2026
**Scope:** the static MiryoLove Web site in this repository, including its current 10 HTML files (nine content pages and the custom 404), shared JavaScript and CSS, local images, page links, and the sampled public HTTP responses. This is a technical inventory, not legal advice.

## Summary

- The reviewed site code does not read or write HTTP cookies (`document.cookie`), and the sampled public responses did not contain a `Set-Cookie` header.
- There are no embedded analytics, advertising pixels, tracking scripts, third-party fonts, or third-party frames. External destinations are ordinary links and are contacted only if a visitor follows one.
- There is no application API, registration, data-submission form, authentication, `fetch`, `XMLHttpRequest`, WebSocket, or `sendBeacon` use in this site.
- The site uses `localStorage` for the visitor-selected interface language and `sessionStorage` to remember dismissal of the informational notice in the current tab session. Neither value is an HTTP cookie or is automatically sent in requests.
- No optional cookies or other optional tracking technologies requiring user choice were found; the notice remains informational.
- The former `miryolove-consent-v1` local-storage record and its accept/reject controls have been removed. The current script attempts to delete that obsolete key from existing browsers.

## Network, scripts, and external services

- Each page loads the repository's own `script.js`, `styles.css`, and local image assets. No third-party JavaScript dependency is included.
- Source searches found no `fetch`, `XMLHttpRequest`, `sendBeacon`, WebSocket, form submission endpoint, or service-worker registration.
- Links to GitHub, Hugging Face, Telegram, and separate MiryoLove project hosts are navigational links, not embedded resources. A browser contacts those hosts only after the visitor follows a link. Their own storage and privacy practices are outside this site audit.
- No analytics or advertising identifiers are present in the reviewed site code. This is an inspection of the website repository and does not establish how an external hosting provider operates.

## HTTP response check

On 4 November 2026, `curl` requests to `https://miryolove.org/`, `https://miryolove.org/script.js`, and `https://miryolove.org/cookies.html` returned HTTP 200. No `Set-Cookie` header was present in those sampled responses. Observed headers included `Strict-Transport-Security`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, and `X-Frame-Options: SAMEORIGIN`.

This is a point-in-time check of three public paths, not a guarantee about every route, future server response, hosting-provider log, or response generated by a separate project. The code changes in this audit are not deployed by this repository task; repeat the response and browser-network checks after deployment.

## Notice behavior

The site now shows a bilingual information notice, not a consent banner. Its close button only dismisses the notice for the current tab session; it does not enable or accept optional processing. The notice uses the existing RU/EN language switch and links to the policy page at `/cookies/`. The source page is `cookies.html`; the clean-route mapping is only proposed in `deploy/miryolove-public-site.caddy` and has not been applied. The default language for a browser without a saved preference is English.
